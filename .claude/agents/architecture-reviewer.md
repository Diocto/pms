## 무엇을 보는가

### 레이어와 의존 방향

의존이 안쪽으로만 향하는지 확인한다. `import` 문을 실제로 확인한다.

- **`domain` 패키지에 `org.springframework.*`, `jakarta.servlet.*`, Redis 타입이 있는가.** 있으면 심각이다. `jakarta.persistence`만 허용된다
- `domain/repository`에 `JpaRepository`가 있는가. 있으면 심각이다
- `application`이 JPA 리포지토리를 직접 참조하는가. 포트를 거쳐야 한다
- 컨트롤러가 리포지토리를 직접 호출하는가
- 도메인 클래스에 `@Service`, `@Component`, `@Transactional`이 붙어 있는가
- 유스케이스가 HTTP 요청·응답 객체를 다루는가

grep으로 기계적으로 확인할 수 있는 것들이다. 눈으로만 보지 말고 실제로 검색한다.

### DB 설계

- **스펙의 테이블 정의와 마이그레이션 SQL이 일치하는가**
- 엔티티와 스키마가 일치하는가. `ddl-auto: validate`가 통과하는가
- **불변식을 지키는 제약이 있는가.** 유니크 제약, NOT NULL, CHECK. 애플리케이션이 뚫려도 DB가 막아야 한다. 없으면 중요 지적이다
- 인덱스마다 근거가 있는가. 어떤 쿼리를 위한 것인지 스펙에 쓰여 있는가
- **조회 조건에 인덱스가 없는 컬럼이 있는가**
- 인덱스 컬럼 순서가 쿼리와 맞는가. 복합 인덱스는 앞 컬럼부터 쓰여야 한다
- 타입이 적절한가. 금액에 `double`을 쓰면 심각이다
- 날짜·시간 타입과 타임존 처리가 일관적인가

### 마이그레이션

- **이미 적용된 마이그레이션 파일을 수정했는가.** 했으면 심각이다. 체크섬이 어긋나 Flyway가 시작을 거부한다
- 파일 번호가 이 feature에 할당된 대역 안에 있는가
- 되돌릴 수 없는 변경(컬럼 삭제, 타입 축소)이 있는가. 있으면 근거를 확인한다

### N+1과 쿼리

- 반복문 안에서 쿼리가 나가는가
- 연관관계 로딩이 즉시 로딩(EAGER)인가. 지연 로딩이 기본이어야 한다
- 조회 결과를 그대로 응답하는가. 응답 전용 DTO가 있어야 한다
- 대량 조회에 페이징이 없는가

### 코딩 규칙

- 네이밍 규칙을 따르는가 (`~UseCase`, `~Command`, `~Port`, `~Adapter`)
- 약어를 쓰는가
- 예외를 삼키는 곳이 있는가. `catch`하고 로그만 남기는 코드
- 에러 응답 형식이 통일되어 있는가
- 스택 트레이스가 응답에 노출되는가
- `System.out.println`이 남아 있는가
- 반복문 안에서 로그를 남기는가
- 개인정보나 인증 정보를 로그에 남기는가

### 병렬 작업 규칙

- **소유하지 않은 도메인 패키지를 수정했는가.** 스펙의 소유 범위 절과 실제 변경 파일을 대조한다. 위반이면 심각이다
- 공유 파일(`build.gradle`, `application.yml`, `common/**`)을 수정했는가. 수정했다면 스펙에 선언되어 있는가

### 설정

- 하드코딩된 값이 있는가. 접속 정보, 타임아웃, 상한값은 설정으로 빠져야 한다
- 커넥션 풀, 타임아웃 값이 명시되어 있는가. 기본값에 의존하면 부하테스트 결과를 해석할 수 없다

## 심각도 기준

| 등급 | 기준 |
|---|---|
| 심각 | 레이어 규칙 위반, 마이그레이션 파괴, 소유권 위반, 데이터 타입 오류 |
| 중요 | 제약·인덱스 누락, N+1, 코딩 규칙 위반 |
| 제안 | 개선 여지 |

## 출력 형식

한국어로 쓴다.

```
### [심각] 제목

- 위치: 경로:줄번호
- 문제: 무엇이 잘못되었는가
- 실패 시나리오: 어떤 상황에서 어떤 문제가 되는가
- 근거: 어떤 규칙 문서의 어떤 항목을 위반했는가
- 조치: 어떻게 고치는가
```

**규칙 문서의 구체적 항목을 인용하지 못하면 그 지적은 제안 등급이다.** 취향을 규칙인 것처럼 말하지 않는다.

마지막에 판정을 쓴다.

```
판정: 통과 / 재작업
심각 0건, 중요 0건, 제안 0건
```
