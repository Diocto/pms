# 의사결정 이력

결정이 하나 정해질 때마다 남긴다. 나중에 몰아 쓰지 않는다. 그때의 제약과 고민은 며칠만 지나도 재구성할 수 없다.

## 언제 남기는가

- 기술이나 라이브러리를 골랐을 때
- 대안 중 하나를 선택했을 때
- 원칙에 예외를 두기로 했을 때
- 무언가를 **하지 않기로** 결정했을 때 (이게 자주 빠진다)
- 이전 결정을 뒤집었을 때

한 줄로 답이 나오는 것은 남기지 않는다. **다르게 갈 수도 있었던 것**만 남긴다.

## 절차

### 1. 새 기술이면 설명이 먼저다

이 프로젝트의 규칙이다. 처음 나온 기술이나 개념이면 **결정하기 전에 관리자에게 설명한다.**

- 이게 무엇인가
- 없으면 어떤 문제가 생기는가
- 대안은 무엇이고 각각 어떤 대가가 있는가

설명 없이 "A를 쓰겠습니다"로 넘어가지 않는다. 관리자가 이해하지 못한 결정은 나중에 설명할 수 없다.

### 2. ADR을 쓴다

`docs/decisions/ADR-0000-<제목>.md`에 `docs/decisions/TEMPLATE.md` 형식으로 쓴다. 번호는 `docs/decisions/INDEX.md`에서 다음 번호를 쓴다.

### 3. 대가와 되돌리는 비용을 반드시 채운다

**대가 없는 결정은 없다.** 못 찾았으면 더 생각한다. 이 절이 비어 있는 ADR은 나중에 읽어도 도움이 안 된다.

되돌리는 비용을 쓰면 지금 얼마나 고민해야 하는지가 정해진다. 싸면 빨리 정하고 넘어간다. 비싸면 지금 신중해진다.

### 4. INDEX에 한 줄 추가한다

`docs/decisions/INDEX.md`에 번호, 제목, 날짜, 상태를 추가한다.

### 5. 새 개념이 나왔으면 학습 노트로 넘긴다

ADR은 "이 과제에서 왜 이걸 골랐나"다. "이 기술이 뭔가"는 학습 노트에 쓴다. `learning-note` 스킬로 제목을 쌓는다.

## 결정을 뒤집을 때

기존 ADR을 고치지 않는다. **새 ADR을 쓰고 기존 것의 상태를 "대체됨"으로 바꾼다.** 왜 뒤집었는지가 기록되어야 한다.

## 흔한 실패

| 증상 | 무엇이 문제인가 |
|---|---|
| 대안 절이 비어 있음 | 비교 없이 고른 것이거나, 비교를 기록하지 않은 것 |
| "채택하지 않은 이유"가 "더 나아서" | 이유가 아니다. 무엇이 어떻게 나은지 써야 한다 |
| 대가 절이 "없음" | 더 생각해야 한다 |
| 문제 절에 제약이 없음 | 나중에 읽으면 왜 그렇게 정했는지 이해할 수 없다 |
