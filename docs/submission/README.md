## 이 프로젝트가 증명하려는 것

세 문장으로 줄이면 이렇습니다.

- **정합성은 DB가 지킨다.** 100실짜리 재고에 20초 동안 6,000건을 밀어넣어도 성공은 **정확히 100건**이고, **분산락을 완전히 꺼도 여섯 번 전부 같았습니다.** 락은 정확성이 아니라 비용을 위한 장치입니다 — 04의 락 대조 실험(S5)이 이 문장의 근거입니다.
- **되돌리는 경로가 더 어렵다.** 취소·결제 실패·시간 만료가 같은 예약에 동시에 도착할 수 있는데, 되돌릴 기회는 한 번뿐입니다. 초과 판매는 손님이 항의해서 발견되지만 **재고를 두 번 되돌린 것은 아무도 발견하지 못합니다.**
- **상태는 표가 정한다.** `(현재 상태, 이벤트) → 다음 상태` 표로만 전이하고, 상태를 직접 바꾸는 수단은 만들지 않았습니다.
- **캐시의 값어치는 옆 기능에서 나온다.** 검색을 초당 500건 흘리면서 캐시를 껐다 켜보니 **검색 자체는 1.3배밖에 안 빨라졌는데 같은 시간 예약이 15.6배 빨라졌습니다.** 검색이 DB 커넥션을 덜 잡아먹은 만큼 예약이 덜 밀린 것입니다 — 캐시가 사는 것은 검색 속도가 아니라 예약이 쓸 커넥션이었습니다(S8).
