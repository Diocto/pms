# 제출 문서

검토관 리뷰용 최종 문서를 여기에 모은다. **이 디렉터리만 읽어도 과제 전체가 파악되어야 한다.**

개발이 끝난 뒤 아래 구성으로 작성한다.

| 파일 | 내용 | 원천 |
|---|---|---|
| `01-문제-정의.md` | 어떤 문제를 왜 골랐는가 | `docs/spec/00-problem-and-scope.md` |
| `02-구현-범위.md` | 어디까지 만들고 무엇을 뺐는가, 그 이유 | `docs/spec/` |
| `03-설계.md` | 도메인 모델, DB, 동시성·멱등성 설계 | `docs/spec/`, `docs/decisions/` |
| `04-부하테스트.md` | 시나리오, 결과, 불변식 검증 | `docs/load-test/report.md` |
| `05-AI-활용.md` | 어떤 AI를 왜 어떻게 썼는가 | 하네스 구조와 `docs/reports/`, `docs/reviews/` 이력 |

원천 문서를 복사하지 않고 **검토관이 읽기 좋게 다시 쓴다.** 과정 기록은 원천에 있고, 여기는 결과와 근거만 깔끔하게 남긴다.
