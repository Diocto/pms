# ADR-0065. 프로모션 잔재를 제거하고 query 계층을 inventory로 통합한다

- 날짜: 2026-08-17
- 상태: 채택
- **결정자: 관리자**

## 문제

코드를 검토하던 관리자가 두 가지를 지적했다.

> "일단 구현된 건 아니니까 빼자. 읽는 입장에서 불편하다. 프로모션 관련 잔재는 모두 제거하자" / "지금은 노이즈는 모두 제거하는 게 나을 것 같다. 할인 관련은 아예 제거하자" / "query라는 계층은 빼자. 지금은 모두 inventory로 통합할 것"

선착순 특가(ADR-0058로 폐기)가 남긴 것이 코드 곳곳에 있었다.

- **확장 훅 4종** — 사전 검사·생성·반납 훅, 할인 해석기. 전부 Protocol 계약과 빈 리스트 프로바이더만 있고 **구현이 0개**
- **할인 입력** — `DiscountRef`·`DiscountType`, Command의 `discounts` 필드. API로 노출된 적도 없다
- 그 계약을 검증하는 테스트 14개

그리고 검색이 `app/inventory/query/` 라는 별도 계층에 있었다 — 병렬 세션 시절 소유권을 가르기 위한 구획이었는데, 세션이 다 끝난 지금은 층 하나가 더 있는 것처럼 읽힌다.

## 결정

**셋 다 제거·통합한다.**

1. 확장 훅 4종과 `ReservationExtensions` 묶음, 빈 리스트 프로바이더, 계약 테스트 14개를 지운다
2. 할인 관련 타입과 필드, 해석 루프를 지운다. 단가는 객실타입 정가 하나다
3. `app/inventory/query/**`를 `app/inventory/**`로 평탄화한다 — `application`·`presentation`은 그대로 올리고, 조회 어댑터는 `infrastructure/search_persistence.py`로, 컨테이너는 `InventoryContainer`로

## 근거

**"확장에 열려 있음을 보여주기 위해 남긴다"는 이유가 더는 성립하지 않는다.** 그 논리로 훅을 남겼는데(03-설계 8절), 실제로 읽는 사람에게는 **어디서도 불리지 않는 코드가 핵심 경로에 끼어 있는 것**으로 보였다. 관리자 TODO가 정확히 그 지점을 짚었다 — "이 hook이라는 거 뭔가 이해하고 추적하기가 어렵다."

**구현 0개인 계약은 증명하는 것이 없다.** 테스트 14개가 지키던 것은 "빈 리스트면 아무 일도 안 일어난다"였다 — 기능이 아니라 자리의 성질이다.

**query 구획의 존재 이유는 병렬 세션의 소유권이었다.** 검색 세션이 예약 세션의 패키지를 건드리지 않게 하는 울타리였고, 세션이 끝난 지금 울타리만 남았다. 읽기 전용이라는 성질은 계층이 아니라 **어댑터의 성질**로 남긴다 — `search_persistence.py`는 여전히 생 SQL로만 읽고 쓰기 모델을 import하지 않는다.

## 지운 것과 남긴 것

| | |
|---|---|
| 지움 | 훅 Protocol 4종, `ReservationExtensions`, 할인 타입·필드·해석 루프, 빈 리스트 프로바이더, 계약 테스트 14개 (312 → 298) |
| 남김 | **설계 기록** — `docs/spec/F02-선착순-프로모션.md`, 03-설계 8절(제거 사실을 머리에 명시), ADR-0058 |
| 남김 | **읽기 전용 성질** — 검색 어댑터는 여전히 쓰기 모델과 분리된 생 SQL |
| 남김 | `LockPolicy` — 프로모션과 무관한 락 사용법 묶음 (ADR-0064) |

## 대가

- 특가류 기능을 다시 넣으려면 확장 지점부터 다시 설계해야 한다. 설계 기록이 남아 있어 백지는 아니다.
- 이 결정은 ADR-0064의 `ReservationExtensions`를 하루 만에 뒤집었다 — 묶음을 만들 게 아니라 내용물을 지웠어야 했다. 순서가 틀렸던 것이고, 기록으로 남긴다.

## 되돌리는 비용

git 이력에 전부 있다. 훅이 실제로 필요해지는 날 이 ADR과 ADR-0058의 설계 기록에서 복원하면 된다.
