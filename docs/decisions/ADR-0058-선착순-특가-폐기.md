# ADR-0058. 선착순 특가(F02)를 범위에서 뺀다

- 날짜: 2026-08-16
- 상태: 채택
- 관련 feature: F02 (폐기), F01·F04에 영향
- **결정자: 관리자**

## 문제

F02는 "한 점에 몰리는 경합"을 보여주려고 넣은 feature다. F01의 경합은 날짜별로 흩어지는데 특가는 잔여 10개짜리 행 하나에 500요청이 몰린다. **방어 수단이 달라진다는 걸 보여주는 것**이 존재 이유였다.

그런데 마감 36시간 시점에 다시 보니 문제가 있었다.

관리자 판단:

> "특가 객실은 숙박/예약에서 메인 문제는 아닌듯하다. 이건 폐기하자."

## 결정

**F02를 구현하지 않는다.** 스펙은 폐기 표시를 달아 남긴다.

## 근거

**이 과제가 보려는 것은 숙박 예약의 동시성이다.** 같은 객실을 여러 사람이 동시에 예약할 때 무슨 일이 벌어지는가.

F01이 그걸 이미 증명했다.

- 잔여 10개에 100명이 동시에 → 성공 정확히 10명
- **분산락을 완전히 꺼도 결과가 같다** → 정합성이 락이 아니라 조건부 UPDATE에 있다
- Redis 멱등 장치를 무력화해도 DB 유니크 제약이 1건을 지킨다
- 겹치는 기간을 반대 순서로 100건 쏴도 데드락 0건

**F02가 더하는 것은 "같은 문제를 다른 데이터 모양에서 한 번 더"다.** 경합점이 여러 행이냐 한 행이냐가 다를 뿐, 막는 방법은 같은 조건부 UPDATE다. 1차 방어가 락이냐 카운터냐는 **비용 최적화의 차이지 정합성의 차이가 아니다** — F02 스펙 스스로 "1차는 정확성에 기여하지 않는다"고 적었다.

**남은 36시간에 무엇을 넣을지의 문제였다.** 같은 증명을 한 번 더 하는 것보다, 이미 증명한 것을 부하테스트로 수치화하고 문서를 다듬는 쪽이 낫다고 봤다.

## 검토한 대안

### 대안 A. 그대로 만든다

- 장점: 단일 행 경합이라는 다른 종류의 문제를 보여준다.
- 채택하지 않은 이유: 마감 36시간에 F03·F04·F05가 함께 남아 있다. F02를 넣으면 **부하테스트 실행 시간이 줄어드는데, 부하테스트는 이 과제의 증명 수단 자체다.**

### 대안 B. 축소해서 만든다 (게이트 없이 조건부 UPDATE만)

- 장점: 싸다.
- 채택하지 않은 이유: **그러면 F01과 완전히 같은 것을 한 번 더 하는 것**이 된다. F02의 차별점이 1차 방어(카운터 게이트)에 있었는데 그걸 빼면 남는 게 없다.

## 대가

- **F02 세션이 만든 문서 2,400여 줄이 구현으로 이어지지 않는다.** 스펙·보고서·Task 목록이 다 있다.
- **F01의 확장 지점 넷에 구현체가 없어진다.** 자리만 남는다.
- "한 점 경합"이라는 다른 종류의 문제를 못 보여준다.

## 버려지지 않는 것

**F02가 만든 규칙이 프로젝트에 남았다.** D16(확장 지점 구현체에 DB 연결을 열 수단을 주지 않는다)이 `coding-rules.md`의 정식 규칙이 됐고, **어느 테스트가 세션 분리를 실제로 잡는가**라는 판별력 표까지 들어갔다.

F01이 그 규칙대로 만들었고, 4회차 리뷰에서 값을 했다. F02가 정지 중에 찾은 반납 훅 테스트 공백도 F01이 자기 목록에 반영했다.

**스펙 자체도 제출에서 쓸 수 있다.** "검토했고 범위에서 뺐다"는 근거 문서다. 안 만든 것에 이유가 있다는 게 안 만든 것보다 낫다.

## 하위 영향

| 대상 | 영향 |
|---|---|
| **F01** | 확장 지점 넷은 그대로 둔다. 구현체가 없을 뿐이고, 자리가 있다는 것이 "확장에 열린 구조"의 증거다 |
| **F04** | 프로모션 부하 시나리오(S7 계열)를 뺀다. F04는 정지 중이라 재개 시 반영한다 |
| **F05** | 영향 없다. 프로모션 화면을 만든 적이 없다 |
| **범위 문서** | UC-7 계열을 제외 목록으로 옮긴다 |
| 에러 코드 | `PROMOTION_NOT_OPEN`·`PROMOTION_SOLD_OUT`을 계약에서 뺀다. 발동할 곳이 없는 코드는 계약을 읽는 사람에게 거짓 신호를 준다 |

## 되돌리는 비용

**싸다.** F02 브랜치가 그대로 남아 있고 F01의 확장 지점도 그대로다. 되살리면 훅 구현체를 붙이는 것부터 시작하면 된다.
