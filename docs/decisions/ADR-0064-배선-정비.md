# ADR-0064. 배선 정비 — 주입은 서명에, 파라미터는 묶음으로, 그릇은 pydantic으로

- 날짜: 2026-08-17
- 상태: 채택
- **결정자: 관리자** (참조 저장소 대조 검토 후 지시)

## 문제

참조 저장소(neo-api-server)와 대조하면서 관리자가 두 가지를 지적했다.

> "의존성 주입이 제대로 활용되고 있지 않다"
> "유스케이스에 command 를 도입한건 좋으나, 유스케이스를 초기화하는데 너무 많은 파라미터가 주어진다."

실측이 지적을 뒷받침했다.

- `@inject`·`Provide` 사용 **0건**, 대신 엔드포인트 12곳이 `request.app.state.container...`로 컨테이너를 직접 뒤졌다. 조립은 컨테이너가 하는데 주입이 없는, 절반짜리였다.
- `CreateReservationUseCase` 생성자 파라미터 **12개** — 포트 5, 시계 1, 정책 원시값 3, 확장 훅 3이 한 줄에 섞여 있었다.
- 전이 유스케이스들은 반대로 `**deps`로 접어 서명이 1개처럼 보였다 — 줄인 게 아니라 안 보이게 한 것.

## 결정

셋을 함께 정비한다.

1. **의존은 서명에 선언한다.** 엔드포인트는 유스케이스를 `Depends(deps.<제공자>)`로 받는다. 컨테이너를 찾아가는 코드는 컨텍스트별 `presentation/deps.py` 한 파일에만 둔다.
2. **생성자 파라미터는 종류별 묶음으로 받는다.** 락의 사용법은 `LockPolicy(lock, wait_s, ttl_s)`, 확장 지점 셋은 `ReservationExtensions(pre_check, creation, discount_resolvers)`. 12개 → **8개**. `**deps` 은폐는 명시 서명으로 되돌린다.
3. **계층을 넘는 그릇은 전부 pydantic으로 통일한다** (관리자 지시: "dataclass 는 쓰지말고 모두 pydantic으로"). 점검 결과 기존 코드는 이미 전부 pydantic이었고(dataclass 0건), 이번에 새로 만든 묶음 둘도 pydantic frozen으로 만들었다.

## neo의 `@inject`+`Provide`를 그대로 안 가져온 이유

참조 저장소는 엔드포인트에 `@inject`와 `Provide[Container.<프로바이더>]`를 쓴다. 처음에는 그대로 가져오려 했고, 중첩 컨테이너에서 동작하는 것까지 스파이크로 확인했다.

**막힌 것은 문법이 아니라 수명이다.** 그 배선은 프로세스 전역이라 **마지막으로 wire한 컨테이너가 이긴다.** neo는 전역 컨테이너 하나라 문제가 없다. 이 프로젝트는 앱 팩토리다 — actuator 테스트가 환경변수를 바꾼 앱을 도중에 만들면, 이미 떠 있는 세션 앱의 주입까지 새 컨테이너로 바뀐다. 훅 계약 테스트는 자기 앱의 컨테이너에 `override`를 거는데, 배선이 다른 컨테이너를 보고 있으면 그 override가 조용히 죽는다.

앱마다 자기 컨테이너를 쓰는 격리는 이 테스트 스위트의 전제라서, FastAPI의 요청 단위 해석(`Depends`)으로 같은 목표를 얻었다 — 서명에 의존이 선언되고, 로케이터 호출이 12곳에서 deps 파일로 모이고, 테스트는 `dependency_overrides`와 컨테이너 override 둘 다 쓸 수 있다.

## 도메인 서비스 층을 안 끼운 이유

neo는 파라미터를 유스케이스↔DAO 사이의 도메인 서비스로 옮겨 줄인다. 여기서는 안 쓴다 — 예약 유스케이스가 무는 것이 락·멱등성·트랜잭션 경계이고, **그게 이 과제가 증명하려는 대상**이다. 서비스 뒤로 감추면 문서가 가리키는 자리와 코드가 있는 자리가 갈라진다. 남은 8개는 서로 종류가 달라 더 묶을 것이 없다.

## 확인

- 테스트 312개 전부 통과 (훅 override 계약, actuator 환경 전환 포함)
- 엔드포인트 본문의 `app.state.container` 접근 0건 (deps 2파일 + actuator 제공자 + 조립 루트만 남음)
- pydantic 묶음의 Protocol 필드는 `runtime_checkable`로 검증까지 동작 확인

## 대가

- deps 파일이라는 간접 층이 하나 늘었다. 컨테이너 프로바이더를 추가하면 deps 함수도 하나 추가해야 한다.
- `runtime_checkable` isinstance는 메서드 존재만 본다 — 서명 불일치는 여전히 호출 시점에 드러난다.
