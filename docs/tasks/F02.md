## 이 목록을 만들 때 지킨 것

- **완료를 판정할 수 있는 단위로 쪼갰다.** 각 Task의 완료 기준이 스펙 테스트 번호나 병합 사실을 가리킨다
- **완료 기준을 관찰 가능한 것으로 썼다.** 전부 "테스트 X가 초록" 또는 "main에 병합됨" 형태다
- **순서에 이유가 있다.** T1(도메인)→T2(스키마)는 TDD 순서, T3(공유 파일)은 뒤 Task들의 예외 코드 전제, T4~T9는 확장 지점 호출 순서대로, T10~T11은 단일 스레드 전부 초록 뒤(스펙 §9-2 규칙), T12~T13은 dev-cycle 마감. **예외: T2의 `down_revision` 한 줄은 F01 병합 후에만 채울 수 있으므로 T2 착수가 그 뒤다**
- **하나가 반나절을 넘지 않는다.** T11(동시성)이 가장 무겁지만 시나리오별 준비·실행·검증이 스펙 §9-1에 이미 설계돼 있어 조립에 가깝다. 넘칠 조짐이면 S1~S4 / S5~S10으로 쪼갠다
