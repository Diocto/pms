## 1. 관리자만 할 수 있는 것 — 지금 막혀 있다

### ① 저장소를 공개할 것인가 🔴 제출이 걸린다

지금 `Diocto/pms`는 **비공개**다. GitHub 링크로 제출하면 검토관이 못 연다.

셋 중 하나를 정해야 한다.

- 공개로 바꾼다
- 검토관을 협력자로 초대한다
- 압축본으로 낸다 (그러면 커밋 이력과 CI 기록이 안 보인다)

**이것만 정해지면 오늘 바로 낼 수 있다.**

### ② Railway 서비스를 만들 것인가 🟡 배포가 여기서 막혀 있다

토큰은 넣으셨고 **정상 동작한다** — CD가 프로젝트에 붙는 것까지 확인됐다. 다음 한 줄에서 멈췄다.

```
Service not found
```

Railway 프로젝트에 서비스가 아직 없다는 뜻이다. 만들 것은 넷이다.

| 서비스 | 무엇 | 설정 |
|---|---|---|
| `MySQL` | DB | Railway 템플릿 |
| `Redis` | 캐시·락 | Railway 템플릿 |
| `pms-api` | 백엔드 | 이 저장소, 루트 `/`, Dockerfile |
| `pms-web` | 화면 | 이 저장소, 루트 `frontend`, Dockerfile |

변수 값과 주의할 점(특히 `mysql+pymysql://`와 빌드 시점 변수)은 [docs/deploy/railway.md](../deploy/railway.md)에 있다.

**배포는 제출을 막지 않는다.** 안 해도 코드·문서·CI는 그대로 낼 수 있다.

### ③ 과제 원본의 제출 형식·채널

원본 과제 문서가 저장소에 없어서 대조할 방법이 없다. 제출물 형식이나 내는 곳에 대한 지시가 따로 있었다면 알려주셔야 한다.

## 2. 관리자 판단 대기 — 제출을 막지는 않는다

### ④ F03 개발 완료 승인

`docs/reports/F03-dev-approval.md`가 게이트에 있다. **코드는 이미 병합됐고** 승인 회신만 남았다. F03의 모든 Task는 닫혔다.

### ⑤ D32 — 확정에서 결제와 커밋의 순서

관리자께서 제안하신 순서("예약·확정을 먼저 걸고 → 결제 → 성공하면 커밋")를 지금 구조와 맞바꿀지의 판단이다.

- **얻는 것:** 환불 보상 경로가 통째로 필요 없어진다
- **치르는 값:** 결제라는 바깥 호출이 트랜잭션 안에 들어와 DB 커넥션을 쥔 채 기다린다

부하테스트가 그 값을 쟀다 — 락 대조에서 경합이 DB로 내려갔을 때 커넥션 점유가 4배, S8에서 검색이 커넥션을 붙들자 예약 p95가 15.6배. 모의 결제는 즉시 끝나 이 비용이 안 보이지만 실제 결제사는 수백 밀리초에서 수 초다.

**PM 의견: 지금 바꾸지 말고 이 맞바꿈을 수치와 함께 문서에 남긴다.** 구현과 테스트가 이미 서 있고, 마감 21시간 전에 트랜잭션 경계를 바꾸면 그 변경을 검증할 시간이 없다.
