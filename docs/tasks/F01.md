## 이 목록을 만들 때 지킨 것

- **완료를 판정할 수 있는 단위로 쪼갰다.** 각 Task가 테스트 번호 묶음 하나에 대응한다. "재고 도메인 구현" 같은 덩어리는 T5(모델)와 T6(조건부 UPDATE)으로 나눴다.
- **완료 기준을 관찰 가능한 것으로 썼다.** 전부 "테스트 X~Y 초록" 또는 "문서가 어디에 있다" 형태다.
- **순서에 이유가 있다.** T1·T2(공유 파일)가 맨 앞인 것은 다른 세션이 기다리기 때문이고, T3(스키마)이 그다음인 것은 F02·F03의 `down_revision` 확정 조건이기 때문이다. 조건부 UPDATE(T6)를 도메인(T8~T10)보다 앞에 둔 것은 스펙 4.2절의 근거 그대로다 — 같은 패턴이 상태 전이에 복제되므로 리뷰를 먼저 받는다. 리뷰 Task(T7·T11·T15·T23)가 회차 사이에 있는 것은 "앞 회차 리뷰가 나오기 전에 다음 회차를 쓰지 않는다"는 규칙이다.
- **하나가 반나절을 넘지 않는다.** 가장 큰 후보였던 "유스케이스 6종"을 T16~T19 넷으로, "K1~K10"을 T21·T22 둘로 나눴다.
