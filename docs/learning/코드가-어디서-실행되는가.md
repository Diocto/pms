# 코드가 어디서 실행되는가 — 서버 컴포넌트와 클라이언트 컴포넌트

**대상 독자: 백엔드 경험이 있는 컴퓨터공학 전공자.** HTTP·상태 머신·트랜잭션은 안다고 전제하고, 브라우저에서 코드가 언제 어디서 도는지는 모른다고 전제한다.

- 분류: 프론트엔드
- 작성일: 2026-08-15
- 처음 마주친 맥락: 예약 화면 세 개를 Next.js로 만들면서, 어느 컴포넌트를 서버에서 그리고 어느 것을 브라우저에서 돌릴지 정해야 했다 (F05 시안 D5)

## 한 줄 정의

같은 코드베이스의 컴포넌트가 **서버에서 한 번 실행되어 HTML이 되는 것**(서버 컴포넌트)과 **브라우저로 배송되어 계속 실행되는 것**(클라이언트 컴포넌트)으로 갈리며, 이 구분이 파일 상단의 `"use client"` 한 줄로 정해진다.

## 왜 존재하는가

백엔드 개발자에게 가장 헷갈리는 지점이 이것이다: **같은 폴더의 같은 .tsx 파일인데 실행 위치가 다르다.** 저장 프로시저(DB에서 실행)와 앱 코드(서버에서 실행)가 같은 저장소에 있는 것과 비슷하다 — 코드가 어디 있느냐가 아니라 어디서 실행되느냐가 능력을 결정한다.

- 서버 컴포넌트는 요청 때 서버에서 실행되고 결과 HTML만 브라우저로 간다. 그래서 DB에 직접 접근할 수 있고, 그 코드는 번들에 실리지 않는다. 대신 **상태·이벤트가 없다** — 실행이 끝나면 사라지는, 백엔드 핸들러와 같은 생명주기다.
- 클라이언트 컴포넌트는 JS로 배송되어 브라우저에서 실행된다. 버튼 클릭·타이머·입력 상태 전부 여기서만 가능하다.

## 어떻게 동작하는가

요청 하나의 흐름: 서버가 서버 컴포넌트를 실행해 HTML 골격을 만들고 → 브라우저가 그 HTML을 즉시 그리고 → 클라이언트 컴포넌트의 JS가 도착하면 그 위에 동작을 붙인다(이 "붙이는" 단계가 하이드레이션, [[하이드레이션]] 참조).

경계 규칙 하나만 기억하면 된다: **서버 컴포넌트는 클라이언트 컴포넌트를 품을 수 있지만, `"use client"`가 붙은 파일이 import하는 것은 전부 클라이언트 번들로 끌려간다.**

## 코드로 보면

```tsx
// layout.tsx — "use client" 없음 = 서버 컴포넌트. 요청마다 서버에서 실행되고 끝.
export default function RootLayout({ children }) {
  return <body><TopNav />{children}</body>;   // 클라이언트 컴포넌트를 품는다
}

// top-nav.tsx — 브라우저에서 계속 산다. 클릭·상태가 있으니까.
"use client";
export function TopNav() {
  const [open, setOpen] = useState(false);   // 서버 컴포넌트에선 컴파일 에러
  ...
}
```

## 언제 쓰고 언제 쓰지 않는가

| 상황 | 선택 | 이유 |
|---|---|---|
| 레이아웃, 정적 안내문 | 서버 | 상태가 없다. JS를 배송할 이유가 없다 |
| 검색 폼, 제출 버튼, 카운트다운 | 클라이언트 | 상호작용과 시간이 본질이다 |
| 자주 바뀌는 데이터의 첫 화면 | 상황에 따라 | 아래 「이 프로젝트에서는」 참조 |

## 흔한 오해와 함정

- "서버 컴포넌트가 더 최신 기술이니 기본으로 써야 한다" — 아니다. **기준은 기술이 아니라 그 화면의 본질이 상호작용이냐다.**
- `"use client"`를 루트에 붙이고 시작하면 전부 클라이언트가 되어 서버 컴포넌트의 이점(번들 제외)이 사라진다. 경계는 "상태가 필요해지는 가장 바깥 지점"에 긋는다.

## 이 프로젝트에서는

세 화면(검색·주문서·상세)의 **본체를 전부 클라이언트 컴포넌트로** 만들었다 (`frontend/app/*/page.tsx`). 서버 컴포넌트는 `layout.tsx`뿐이다.

검색 결과를 서버 컴포넌트로 미리 그리는 안을 검토하고 기각했다. 이 시스템의 검색 결과는 캐시 때문에 최대 10초 낡을 수 있는 데이터다. 서버에서 미리 그려 봤자 하이드레이션 직후 다시 물어봐야 하고, 그러면 "서버가 그린 낡은 값 → 새 값"으로 화면이 두 번 바뀐다. 어차피 브라우저에서 다시 조회할 데이터라면 처음부터 클라이언트에서 조회하는 쪽이 단순하다. 이 판단이 시안 D5로 승인됐다.
