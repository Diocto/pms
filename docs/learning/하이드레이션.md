# 하이드레이션 — HTML과 동작 사이의 틈

**대상 독자: 백엔드 경험이 있는 컴퓨터공학 전공자.**

- 분류: 프론트엔드
- 작성일: 2026-08-15
- 처음 마주친 맥락: 사용자 식별값을 localStorage에 보관하는 컴포넌트를 만들다가, 저장된 값을 "언제" 읽어야 하는지가 버그의 경계였다 (`frontend/components/user-context.tsx`)

## 한 줄 정의

서버가 만들어 보낸 완성된 HTML 위에, 나중에 도착한 자바스크립트가 이벤트 핸들러와 상태를 붙여 "동작하는 화면"으로 되살리는 과정이다.

## 왜 존재하는가

HTML만 먼저 보내면 사용자는 빈 화면 대신 내용을 즉시 본다. 하지만 그 HTML은 아직 죽어 있다 — 버튼을 눌러도 반응이 없다. JS가 도착해서 하이드레이션이 끝나야 산다. 즉 **모든 페이지에는 "보이지만 동작하지 않는 구간"이 존재한다.**

백엔드에 빗대면: 배포 중 구버전과 신버전이 잠깐 섞이는 순간과 같은 종류의 문제다. 두 시점의 산출물(서버가 그린 HTML, 브라우저가 계산한 첫 렌더)이 **반드시 일치해야 한다**는 제약이 생기고, 어긋나면 프레임워크가 하이드레이션 불일치 오류를 낸다.

## 어떻게 동작하는가

1. 서버가 컴포넌트를 실행해 HTML 생성 → 전송. 사용자는 이걸 본다.
2. 브라우저가 JS 번들 다운로드·실행.
3. React가 같은 컴포넌트를 **브라우저에서 한 번 더 실행**하고, 그 결과가 서버 HTML과 같은지 대조하면서 이벤트를 붙인다.
4. 이때 결과가 다르면 — 서버는 A를 그렸는데 브라우저 첫 렌더가 B면 — 불일치다.

불일치의 전형적 원인: **브라우저에만 있는 값**(localStorage, 현재 시각, 화면 크기)을 첫 렌더에서 읽는 것. 서버에는 그 값이 없으니 두 실행 결과가 다를 수밖에 없다.

## 코드로 보면

```tsx
// 틀린 판: 서버에는 localStorage가 없다 → 서버 HTML(기본값)과
// 브라우저 첫 렌더(저장값)가 달라져 하이드레이션 불일치
const [userId, setUserId] = useState(
  localStorage.getItem("userId") ?? DEFAULT,
);

// 맞는 판: 첫 렌더는 양쪽 다 기본값으로 같게 만들고,
// 마운트 뒤(=하이드레이션 뒤에만 실행되는 useEffect)에 저장값으로 바꾼다
const [userId, setUserId] = useState(DEFAULT);
useEffect(() => {
  const saved = localStorage.getItem("userId");
  if (saved) setUserId(saved);
}, []);
```

## 언제 신경 쓰는가

| 상황 | 위험 | 이유 |
|---|---|---|
| 브라우저 저장소·시계·랜덤을 첫 렌더에 쓸 때 | 높음 | 서버와 값이 다르다 |
| 정적 텍스트·서버 데이터만 그릴 때 | 없음 | 두 실행이 같은 입력을 본다 |
| "동작 전 클릭"이 문제가 되는 버튼 | 중간 | 하이드레이션 전 클릭은 무시된다 — 중요한 버튼이면 완료 전 비활성 표시를 고려 |

## 흔한 오해와 함정

- "서버 렌더링을 안 쓰면(전부 클라이언트 컴포넌트면) 하이드레이션이 없다" — Next.js는 클라이언트 컴포넌트도 **첫 HTML은 서버에서 미리 그린다.** `"use client"`는 하이드레이션 면제가 아니다. 나도 이걸 처음 틀리게 알고 있었다.
- 시각 표시의 함정: `new Date()`를 렌더에서 직접 부르면 서버 시각과 브라우저 시각이 달라 불일치가 난다.

## 이 프로젝트에서는

- `frontend/components/user-context.tsx` — 위 "맞는 판" 코드 그대로. 사용자 식별값은 마운트 후 useEffect에서 읽는다.
- `frontend/app/reservations/[code]/page.tsx`의 카운트다운 — 남은 시간을 렌더 중에 계산하지 않고, **응답을 받은 순간**(useRef에 고정)을 기준으로 만든 초기값에서 1초씩 줄인다. 시각을 렌더에서 읽지 않으니 불일치가 없다.
