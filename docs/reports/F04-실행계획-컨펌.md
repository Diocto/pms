# [F04] 컨펌 요청: 부하테스트 실행 계획

- 날짜: 2026-08-16
- 단계: 실행 전 시나리오 컨펌 (관리자 지시로 신설된 게이트)
- 판정 요청: **"이대로 돌려도 된다" / "이건 빼고 돌려라" / 재작업**

## 한눈에 보기

- 무엇을 돌리나: 예약 시스템에 가짜 손님 수백 명을 동시에 밀어넣는 실험 7종
- 무엇이 나오나: "동시에 몰려도 초과 판매·중복 예약·금지 전이가 0건"이라는 수치 증거
- 전부 돌리면: 약 2시간 45분. 최소로 줄이면 약 2시간
- 리스크: 없음 — 로컬 전용이고, 실험 전 초기화 스크립트가 로컬이 아니면 스스로 멈춘다
- 검색 실험 2종은 이 문서 밖이다 — F03 병합 후 따로 컨펌받는다

## 1. 회차마다 무엇을 알게 되고, 무엇이 나와야 통과인가

| 순서 | 실험 | 이걸 돌리면 알게 되는 것 | 통과 조건 | 소요 |
|---|---|---|---|---|
| 0 | 준비 검증 | 검증 도구 자체가 고장 나 있지 않은가 (일부러 깨뜨려 보고 잡는지 확인) | 심어둔 오류 3종을 전부 잡음 | 10분 |
| 1 | S1 순간 집중 | 방 10개에 200명이 동시에 달려들면 | 성공 정확히 10건, 재고 음수 0 | 10분 |
| 2 | S3 재요청 폭주 | 같은 요청을 여러 번 보내면 (새로고침 연타) | 예약은 키당 1건, 첫 응답만 201 나머지 200 | 15분 |
| 3 | S4 취소×확정 | 취소와 결제 확정이 동시에 도착하면 | 규칙 밖 상태 변화 0건 | 15분 |
| 4 | S4-B 만료×확정 | 자동 만료와 결제 확정이 겹치면 | 재고가 두 번 돌아오는 일 0건 | 15분 |

| 8 | S6 혼합 5분 | 생성·취소·확정을 섞어 오래 돌리면 재고가 새나 | 재고+예약 합계가 처음과 일치 | 25분 |

모든 회차 공통: 서버 오류(500) 1건이라도 나오면 그 회차는 실패로 기록한다. 합격선은 전부 실행 전에 확정된 값이라(이 표와 설계 문서), 결과를 보고 기준을 맞추는 일은 없다.

## 2. 얼마나 걸리는가

전부 돌리면 2시간 45분이다. 실행 중 문제가 나와 한 회차를 다시 돌 여유까지 보면 3시간 반을 잡아야 한다. 마감까지 34시간이므로 전부 돌리고도 리포트 쓸 시간은 남는다.

## 3. 빼도 되는 것과 못 빼는 것

시간을 줄여야 하면 아래 순서로 뺀다. 어디까지 뺄지는 관리자가 정한다.

| 실험 | 빼면 잃는 것 | 아끼는 시간 |
|---|---|---|
| S6 혼합 5분 | 장시간 안정성 증거. 개별 명제는 앞 실험들이 이미 증명 | 25분 |
| S2 지속 부하 | "순간이 아니라 계속 몰려도"라는 판본. 명제 자체는 S1이 증명 | 15분 |
| S1-C 부분 소진 | 경계 판정(잔여 2에 3개 요청 거절)의 증거. 가장 어려운 판본이라 아깝다 | 10분 |

**S1·S3·S4·S4-B·S5와 0번 검증은 못 뺀다.** 이 다섯이 과제가 요구한 명제 네 개(초과 판매·중복·금지 전이·상대 비교)의 최소 집합이고, 0번이 빠지면 나머지 결과 전체를 믿을 근거가 없다.

## 4. 이 환경에서 못 재는 것

- **절대 성능 수치.** 앱·DB·부하 도구가 전부 한 노트북에서 돌아 서로 자원을 뺏는다. "초당 몇 건 처리"는 이 머신의 숫자일 뿐이라, 리포트는 켜고 끈 차이 같은 상대 비교 중심으로 쓴다.
- **극한 동시성.** 동시에 처리되는 요청 수가 프로세스당 DB 연결 15개 상한에 먼저 걸린다. 그 상태의 지연은 락 경합이 아니라 연결 대기를 잰 것이라, 상한에 닿았는지를 회차마다 확인하고 닿았으면 그렇게 적는다.
- **진짜 네트워크.** 부하 도구가 같은 머신에서 쏘므로 네트워크 지연·유실은 실험에 없다.

이 한계는 전부 리포트 명시 대상이고 리포트 골격에 이미 자리가 있다.

## 5. 결정 검토란

- **D1. 특가 실험 3종을 뺐다.** 이유: F02 폐기(ADR-0058)로 대상 기능이 없다. 스크립트는 삭제, 설계는 폐기 표시로 보존. — 동의하십니까?
- **D2. 실행 순서는 "짧고 명확한 명제부터"다.** 이유: 중간에 시간이 끊겨도 핵심 증거가 먼저 확보된다. 트레이드오프: 가장 오래 걸리는 락 대조(S5)가 뒤로 가서, 초반 중단 시 (라) 명제를 잃는다. 대안(S5 먼저)은 반대로 사고 시 (가)(나)(다) 전부를 잃어 버렸다. — 동의하십니까?
- **D3. 위 3절의 절단 순서(S6 → S2 → S1-C)를 기본값으로 둔다.** 관리자가 "줄여라"고만 답해도 이 순서대로 뺀다. 특정 실험을 지목해 빼도 된다. — 이대로 둘까요, 지금 뺄 것을 정하시겠습니까?

**답 주시면 그 시점부터 실행에 들어간다.** 전부 승인이면 0번부터 순서대로 돌고, 회차마다 초기화 → 부하 → 검증 세 단계의 종료 코드가 기록으로 남는다.
