## 0. 불리한 것 먼저

1. **카운트다운 0 도달 재조회가 리뷰 라운드 1(제안)→2(중요)→3(중요)로 세 라운드 연속 지적됐다.** 라운드2의 수정이 새 결함(React effect 재실행과의 상호작용)을 만들었고 라운드3에서 잡혔다. 원인은 타이밍 로직이 컴포넌트 안에 있어 테스트 밖이었던 것 — 판정을 순수 함수(`lib/countdown.ts`)로 추출해 테스트를 붙이는 구조 변경으로 닫았고, 라운드4에서 세 리뷰어가 확인했다. dev-cycle의 "같은 지적 연속" 신호에 해당해 여기 명시한다.
2. **리뷰 라운드2 문서에 "수정함"으로 기록했으나 실제로는 미적용이었던 항목이 1건 있었다** (SALES_CHECKOUT_LIMIT — 상수 선언만 하고 사용처 교체 누락). 라운드3 리뷰어가 발각했고, 코드 수정과 함께 round2 문서를 "정정" 표기로 고쳤다. 라운드4에서 git 이력 대조로 재검증됐다.
3. **실 백엔드로는 아무것도 검증되지 않았다.** F01 API가 아직 없어 모든 검증이 가짜 백엔드(계약 문서 기준 구현) 위다. 계약 문서와 실제 구현이 다르면 T6에서 어긋남이 드러난다 — 그 대조 비용을 줄이려고 가정 대장을 만들어 뒀다(4절).
4. **화면 컴포넌트의 브라우저 렌더링 테스트는 없다.** 115건은 전부 로직 계층(lib/)이다. React 렌더링·훅 상호작용은 리뷰어의 코드 추적으로만 검증됐다 (9절 판단 요청).
5. **작업 중 사고 2건:** 워크트리 루트에서 node 명령을 실행해 빌드 부산물이 커밋에 두 번 섞였다. 즉시 제거했고(705a49a) 루트 .gitignore 두 줄로 재발을 막았다(c9b2c0c, PM 통지 후 main 병합됨).

## 1. 무엇을 만들었는가

**문제.** 이 시스템은 검색 결과가 최대 10초 낡을 수 있게 설계되어(F03 캐시), "예약 가능"으로 보이는 방이 누르는 순간 없을 수 있다. 화면이 이 실패를 "오류"로 뭉개면 설계의 증거가 사라진다. 또한 멱등성 키는 클라이언트가 만들므로, 키의 수명 관리가 틀리면 서버의 멱등성 구현 전체가 무의미해진다.

**해법.** 승인된 시안(D1~D9)대로:

- **409 = 정상 흐름:** "방금 마감" 통보 → `fresh=true` 재검색 → 같은 키로 자동 재시도(최대 2회) → 대안 안내. 수동 재시도 버튼 없음.
- **멱등성 키 수명:** 주문서 진입 시 1회 발급, 연타·타임아웃·409 재시도 전부 같은 키. 사용자 식별값 변경 = 다른 시도 = 새 키.
- **결제 거절(200 + CANCELLED)은 본문 status로 분기** — 성공 화면과 완전 분리.
- **만료 판정은 서버 몫:** 카운트다운 0에서 화면이 스스로 만료 처리하지 않고 재조회(폴링 상한 1req/s).
- **상태 6종 × 표기·행동 매핑 한 곳** (`reservation-view.ts`) — 서버 전이표와 어긋나면 409 → 재조회 수렴 + 안내 배너.

## 4. 동시성과 멱등성 — 화면의 몫

백엔드의 락·트랜잭션·DB 제약은 이 feature 범위 밖이다(브리핑: 프론트는 증명에 기여하지 않는다). 화면이 지는 계약과 검증 방법:

| 계약 | 이행 | 검증 |
|---|---|---|
| 같은 시도 = 같은 키 | 진입 시 1회 발급(useState), 모든 재시도 경로 공유 | api.test: 4요청 전부 같은 키 단언 |
| 409 자동 재시도 상한 2회 | booking-flow 오케스트레이터 | 6건 (호출 횟수·순서·중단 조건) |
| REQUEST_IN_PROGRESS 같은 키 재요청 상한 | api 계층 재시도 3회(총 4요청) + 소진 후 같은 키 "다시 시도" 동선 | api.test 2건 |
| 200+CANCELLED ≠ 성공 | 본문 status 분기 | api.test·mock.test·view.test |
| 만료 판정 서버 위임 + 폴링 상한 | expiryFireDelayMs(0이하 마운트→1초 지연) | countdown.test 10건 + 라운드4 추적 |
| 이중 복원·이중 예약 방지(가짜 서버) | settleExpiry 가드·(userId,key) UK 흉내 | mock.test 54건 (전이 24칸 전수 포함) |
| 낡은 응답이 화면 덮어쓰기 방지 | 요청 순번 가드 (상세·주문서) | 라운드4 추적 확인 |

**"1차 방어선을 껐을 때" 절은 해당 없음** — 분산락은 백엔드 소관이다. 화면 쪽 대응물은 "가짜 서버의 멱등 키 선점이 뚫려도 (userId,key) UK 흉내가 막는다"이며 mock.test가 검증한다.
