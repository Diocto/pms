## 세 리뷰가 수렴한 핵심 재작업 — "판정 기준을 재조회로 옮기지 말라"

**문제:** 전이 유스케이스가 write 트랜잭션에서 상태를 **재조회해 판정을 다시 세웠다.** 그래서 경합 패배가 넓은 창에서 `거부 예외`나 `멱등`으로 위장됐다:
- 취소·체크인이 패배 시 스펙의 409 대신 **200 + 승자의 상태**를 반환 (사용자가 취소 성공으로 오인)
- 확정의 **환불 보상 경로가 밀리초 창에서만 도달 가능** — 만료·취소가 먼저 커밋하면 환불 없이 409, 이중 확정 창에서는 멱등 200 + **결제 2건 잔존**
- 만료가 정상 경합 패배를 "만료 처리 실패" 오류 스택트레이스로 위장

**반영:** 행동을 정당화한 기대 상태를 조건부 UPDATE에 그대로 걸고(`apply_event(current=expected)`), `lost`를 UC별 스펙 행대로 처리 — 취소·체크인·체크아웃 **409**, 확정 **환불+409**(승인 후 못 이긴 모든 경우가 이 분기 하나로 수렴, **D32**), 만료 **조용히 skip**. 스텁 기반 유닛 테스트 4개로 각 분기를 결정적으로 고정 (`test_transition_races.py`).
