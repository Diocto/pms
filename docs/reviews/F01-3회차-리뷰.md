## 중요 9건 — 전부 반영

- **[도메인] "재고 부족 키 유지"가 3상태로는 성립 불가** — 재요청이 `REQUEST_IN_PROGRESS`로 둔갑. → **D30 결정**: `FAILED:{코드}` 상태 추가, `store_failure()`/`failed` outcome. 재요청이 같은 409를 받는다
- **[도메인+아키] 확장 지점 시그니처가 스펙 3.6과 불일치** — F02가 문서만 보고 구현하면 통합 시 TypeError. → **`commands.py`를 앞당겨 생성**(DiscountType·DiscountRef·OrderLine·CreateReservationCommand), 포트를 스펙 블록과 한 줄씩 일치(`resolve(session, ref, room_type_id, period: StayPeriod)`, `AppliedDiscount.ref`, ReleaseHook enum 타입). `object` 잠정 타입 전부 소멸
- **[도메인] `FakePaymentAdapter` 무테스트 커밋 (절대 규칙 위반)** — declined 분기를 맞바꿔도 전부 초록이었다. → 규약 표 소급 테스트 3개 (결정성 100회·거절 사유·무예외)
- **[동시성] 대기 상한 테스트에 판별력 없음** — 키마다 상한을 줘도 통과. → 가짜 시계 + 스파이 락으로 `blocking_timeout`이 소모분만큼 줄어드는지 직접 단언 (0.5→0.4→0.3)
- **[동시성] 멱등 경합 테스트 부재** — 비원자 구성으로 바꿔도 초록. → Barrier 30스레드 동시 claim → `acquired == 1`·`processing == 29`
- **[동시성] 밀리초/초 변환 지점 부재** — `wait_s=lock_wait_millis`면 200초 대기, 잡을 장치 없음. → 컨테이너에 **유일한 변환 프로바이더** `lock_wait_s` 신설, 유스케이스는 이것만 주입
