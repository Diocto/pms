## 지적 사항

### [중요] TTL 비연장 테스트가 초 단위 반올림 때문에 GETEX 회귀를 못 잡는다

- **리뷰어:** concurrency-reviewer, architecture-reviewer (독립 교차 지적)
- **위치:** `tests/test_search_cache_redis.py` `test_T15_조회는_TTL을_연장하지_않는다`
- **문제:** Redis `TTL` 명령은 초 단위 반올림이라, put 직후 `ttl_before=10`이고 GETEX가 만료를 풀 리셋해도 최종값이 10이어서 `10 <= 10`으로 통과한다. 1회차 [중요] 지적("검증이 없다")을 막으려 넣은 테스트가 잡으려던 회귀에 대해 판별력이 0이다.
- **근거:** tdd.md "실패를 눈으로 확인한다 — 통과하는 걸 보고 넘어가면 그 테스트는 아무것도 검증하지 않을 수 있다", 스펙 9절 헛통과 원칙.
- **조치:** `PTTL`(밀리초)로 교체 + put과 get 사이 20ms 대기 + 엄격 감소(`<`) 단언.
- **처리:** **수정함.** 어댑터 `get`을 임시로 `GETEX`로 바꿔 **빨강을 실측으로 확인**(`assert 10000 < 9999` 실패 — 리셋이 정확히 잡힌다)한 뒤 원복, 초록 확인.

### [참고] 스펙 9절 C2 헛통과 표의 처방이 재설계 이후 낡았다

- **리뷰어:** concurrency-reviewer
- **위치:** 스펙 9절 헛통과 표 C2 행 — "쏠리면 검색 스레드 수를 늘려 재현율을 올린다"는 확률적 처방이 남아 있었다. 재설계는 두 신호로 쏠림을 결정적으로 없앴으므로 스펙이 구현을 못 따라온 상태.
- **처리:** **수정함(문서).** 두 신호 설계로 교체, 정정 일자 명기.
